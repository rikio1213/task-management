## 1. プロジェクト概要

### 背景・課題

現状、タスクをメモや口頭で管理しているため、以下の問題が発生している。

- 何が完了していて、何が残っているか把握しづらい
- タスクの対応状況を共有・確認する手段がない
- 作業の抜け漏れが起きやすい

### 目的

カンバンボード形式のタスク管理アプリを構築し、上記の課題を解決する。
タスクを「未着手・進行中・完了」の3ステータスで視覚的に管理できるようにする。

### 成果物

| 成果物 | 説明 |
|--------|------|
| Webアプリケーション | ブラウザで動作するタスク管理システム |
| ソースコード | GitHub上で管理・納品 |
| 本要件定義書 | 仕様の合意文書 |

## 2. 前提条件・制約

| 分類 | 内容 |
|------|------|
| **開発環境** | Java 17以上、Node.js 18以上がインストールされていること |
| **実行環境** | 最新バージョンのChrome・Edge・Safariで動作すること |
| **データ保存** | データはサーバーサイドのデータベースに永続化する |
| **認証** | 今回のスコープではユーザー認証は実装しない |
| **利用人数** | 個人利用（1ユーザー）を前提とする |
| **ネットワーク** | アプリの利用にはインターネット接続が必要 |
| **ソース管理** | GitHubにてソースコードを管理する |

## 4. 用語集

| 用語 | 説明 |
|------|------|
| **カンバンボード** | タスクを列（カラム）に分けて進捗を管理する手法。Trelloが有名。 |
| **カラム** | ボード上の縦列。このアプリでは「未着手」「進行中」「完了」の3つ。 |
| **カード** | 1つのタスクを表す表示単位。カラムの中に並ぶ。 |
| **ステータス** | タスクの進捗状態。`TODO`・`IN_PROGRESS`・`DONE` の3種類。 |
| **API** | フロントエンド（React）とバックエンド（Spring Boot）が通信するための接続口。REST形式を採用。 |
| **CRUD** | Create（作成）・Read（取得）・Update（更新）・Delete（削除）の頭文字。データ操作の基本4種類。 |
| **フロントエンド** | ブラウザ上で動く画面側の処理。このアプリではReactを使用。 |
| **バックエンド** | サーバー側の処理。このアプリではSpring Bootを使用。 |
| **DB（データベース）** | データを永続的に保存する場所。タスクデータをここに記録する。 |

## 5. システム構成

### 技術スタック

| レイヤー | 技術 | 役割 |
|---------|------|------|
| フロントエンド | React | ブラウザ上の画面表示・操作 |
| バックエンド | Spring Boot（Java） | ビジネスロジック・APIの提供 |
| データベース | MySQL | タスクデータの永続化 |
| バージョン管理 | GitHub | ソースコード管理 |
| AI連携 | Claude（Anthropic） | 品質チェック・開発支援 |

### システム構成図

```
[ ブラウザ ]
    ↕ HTTP/REST
[ フロントエンド: React ]
    ↕ REST API (JSON)
[ バックエンド: Spring Boot ]
    ↕ SQL
[ データベース: MySQL ]
```

### 開発フロー

```
要件定義 → 設計 → Spring Boot実装（API）→ React実装（画面）→ 結合 → デバッグ
```

## 6. 機能要件

> **必須** = 必ず実装する機能 / **任意** = 余裕があれば追加する機能

| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F-01 | タスク一覧表示（Read） | 登録済みのタスクをカンバンボード形式で表示する | 必須 |
| F-02 | タスク新規登録（Create） | タイトルを入力して新しいタスクを作成できる | 必須 |
| F-03 | タスクステータス更新（Update） | タスクを「未着手→進行中→完了」と進められる | 必須 |
| F-04 | タスク内容編集（Update） | タスクのタイトルを後から変更できる | 必須 |
| F-05 | タスク削除（Delete） | 不要なタスクを削除できる（確認あり） | 必須 |
| F-06 | カラム別表示 | ステータスごとに列を分けて表示する | 必須 |
| F-07 | カード枚数表示 | 各カラムにタスク枚数をバッジで表示する | 任意 |
| F-08 | ドラッグ＆ドロップ | カードをドラッグして列間を移動できる | 任意 |

## 7. ユースケース

ユースケースとは「ユーザーがアプリをどう使うか」を操作の流れで記述したものです。

---

### UC-01 タスクを追加する

| 項目 | 内容 |
|------|------|
| **アクター** | ユーザー |
| **事前条件** | アプリがブラウザで開かれている |

**操作手順**

1. 「＋ タスクを追加」ボタンを押す
2. タスクのタイトルを入力する
3. 「追加」ボタンを押す

**結果**

- 入力したタイトルのタスクが「未着手」カラムに追加される
- データがDBに保存される

**例外**

- タイトルが空のまま送信しようとすると、エラーメッセージが表示されて登録されない

---

### UC-02 タスクを進める

| 項目 | 内容 |
|------|------|
| **アクター** | ユーザー |
| **事前条件** | タスクが存在し、「完了」ステータスではない |

**操作手順**

1. 進めたいタスクカードの「進める →」ボタンを押す

**結果**

- タスクが1つ右のカラムに移動する（例：未着手 → 進行中）
- DBのステータスが更新される

**例外**

- 「完了」カラムのタスクは「進める →」ボタンが押せない（無効化）

---

### UC-03 タスクを編集する

| 項目 | 内容 |
|------|------|
| **アクター** | ユーザー |
| **事前条件** | 編集したいタスクが存在する |

**操作手順**

1. 編集したいタスクカードのタイトルをクリックする
2. タイトルが入力欄に変わる
3. 内容を書き換える
4. `Enter` キーを押すか、入力欄の外をクリックして確定する

**結果**

- タスクのタイトルが新しい内容に更新される
- DBに変更内容が保存される

**例外**

- `Esc` キーを押すと変更がキャンセルされ、元のタイトルに戻る
- タイトルを空にして確定しようとすると、変更されずに元に戻る

---

### UC-04 タスクを削除する

| 項目 | 内容 |
|------|------|
| **アクター** | ユーザー |
| **事前条件** | 削除したいタスクが存在する |

**操作手順**

1. 削除したいタスクカードの「✕」ボタンを押す
2. 「このタスクを削除しますか？」という確認ダイアログが表示される
3. 「OK」を押して削除を確定する

**結果**

- タスクがボードから削除される
- DBからデータが削除される

**例外**

- 確認ダイアログで「キャンセル」を押すと、削除されずにそのまま残る

## 9. データ要件

### エンティティ定義

アプリが扱うデータの構造（DBのテーブル設計の元になる）。

#### Task（タスク）テーブル

| カラム名 | 型 | 説明 | 制約 |
|---------|-----|------|------|
| `id` | BIGINT | タスクの一意識別子 | PRIMARY KEY, AUTO_INCREMENT |
| `title` | VARCHAR(255) | タスクのタイトル | NOT NULL |
| `status` | ENUM | 進捗ステータス | NOT NULL, デフォルト: `TODO` |
| `created_at` | DATETIME | 作成日時 | NOT NULL, 自動設定 |
| `updated_at` | DATETIME | 最終更新日時 | NOT NULL, 自動更新 |

#### ステータスの定義

| 値 | 表示名 | 説明 |
|----|--------|------|
| `TODO` | 未着手 | まだ着手していないタスク |
| `IN_PROGRESS` | 進行中 | 現在対応中のタスク |
| `DONE` | 完了 | 完了したタスク |

## 10. API概要

フロントエンド（React）からバックエンド（Spring Boot）を呼び出すためのREST APIの一覧。

| メソッド | エンドポイント | 機能 | 対応ユースケース |
|---------|--------------|------|----------------|
| `GET` | `/api/tasks` | タスク全件取得 | UC-01の前提（画面表示時） |
| `POST` | `/api/tasks` | タスク新規登録 | UC-01 |
| `PUT` | `/api/tasks/{id}` | タスク内容更新（タイトル変更） | UC-03 |
| `PATCH` | `/api/tasks/{id}/status` | タスクステータス更新 | UC-02 |
| `DELETE` | `/api/tasks/{id}` | タスク削除 | UC-04 |

> **補足：** `PUT` はデータ全体の更新、`PATCH` は一部（ステータスのみ）の更新に使用する。

## 11. 非機能要件

| 分類 | 要件 |
|------|------|
| **動作環境** | 最新バージョンのChrome・Edge・Safariで正常に動作すること |
| **レスポンシブ** | PC（1280px以上）・スマートフォン（400px程度）の両方で崩れずに表示されること |
| **パフォーマンス** | タスクの一覧表示・追加・更新・削除が3秒以内に完了すること |
| **データ永続性** | タスクデータはDBに保存し、ブラウザを閉じてもデータが消えないこと |
| **セキュリティ** | 入力値はバックエンドでバリデーションを行い、不正なデータの登録を防ぐこと |
| **保守性** | フロントエンド（React）とバックエンド（Spring Boot）を分離し、独立して変更できる構成にすること |
| **ソース管理** | GitHubのリポジトリで管理し、変更履歴を追跡できること |

## 12. スコープ外（今回は作らないもの）

以下の機能は今回の開発対象に含まない。必要であれば将来のバージョンで検討する。

| 機能 | 理由 |
|------|------|
| ユーザー認証（ログイン・ログアウト） | 個人利用のためスコープ外 |
| 複数ユーザーでの共同利用 | 認証機能が前提となるためスコープ外 |
| タスクの期限・優先度設定 | 初版では基本機能のみに絞る |
| 通知機能（リマインダー） | スコープを広げすぎないため対象外 |
| ドラッグ＆ドロップ移動 | ボタン操作で代替できるため任意扱い |
| ファイル添付機能 | 要件として挙がっていないため対象外 |
