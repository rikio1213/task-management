| 項目 | 内容 |
|------|------|
| ドキュメント種別 | 要件定義書 |
| バージョン | 1.0 |
| 作成日 | 2026年10月13日 |
| ステータス | 初版 |

---

## 1. プロジェクト概要

**目的**
日々のタスクの進捗状況を視覚的に把握できるようにする。
やるべきことが「どの段階にあるか」を一目で確認できる個人用タスク管理ツールを作成する。

**背景・課題**
タスクをメモや頭の中だけで管理していると、何が終わっていて何が残っているかが不明確になりやすい。
カンバンボード形式（Trello風）で可視化することで、作業の抜け漏れと優先度の把握を改善する。

**成果物**
ブラウザで動作するシングルページのWebアプリ（`index.html` 1ファイル）

---

## 2. 対象ユーザー

| 項目 | 内容 |
|------|------|
| 主なユーザー | 作成者本人（個人利用） |
| 利用シーン | 学習・勉強・日常のタスクを管理するとき |
| 想定デバイス | PC（メイン）／スマートフォン（サブ） |
| 技術レベル | ITの基礎的な操作ができれば使える（専門知識は不要） |

---

## 3. 用語集

| 用語 | 説明 |
|------|------|
| **カンバンボード** | タスクを列（カラム）に分けて進捗を管理する手法。Trelloが有名。 |
| **カラム** | ボード上の縦列。このアプリでは「未着手」「進行中」「完了」の3つ。 |
| **カード** | 1つのタスクを表す四角いブロック。カラムの中に並ぶ。 |
| **localStorage** | ブラウザが持つデータ保存の仕組み。サーバー不要でデータを残せる。 |
| **シングルページ** | HTMLファイルが1つだけで、ページ遷移のないアプリ構成。 |

---

## 4. 機能要件

> **必須** = 必ず実装する機能 / **任意** = 余裕があれば追加する機能

| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F-01 | カラム表示 | 「未着手」「進行中」「完了」の3列を横並びで表示する | 必須 |
| F-02 | カード追加 | 各列にタイトルを入力して新しいタスクカードを追加できる | 必須 |
| F-03 | カード削除 | 不要なカードを削除できる（確認ダイアログあり） | 必須 |
| F-04 | カード編集 | カードのタイトルをクリックして直接書き換えられる | 必須 |
| F-05 | 列間の移動 | 「進める」「戻す」ボタンでカードを隣の列へ移動できる | 必須 |
| F-06 | データ保存 | ブラウザを閉じてもタスクが消えないよう自動保存する（localStorage利用） | 必須 |
| F-07 | カード枚数表示 | 各列にカード枚数をバッジで表示する | 任意 |
| F-08 | ドラッグ＆ドロップ | カードをドラッグして直感的に列間を移動できる | 任意 |

## 5. ユースケース

ユースケースとは「ユーザーがアプリをどう使うか」を操作の流れで記述したものです。

---

### UC-01 タスクを追加する

| 項目 | 内容 |
|------|------|
| **アクター** | ユーザー |
| **事前条件** | アプリがブラウザで開かれている |

**操作手順**

1. 追加したいカラム（例：未着手）の「＋ カードを追加」ボタンを押す
2. テキスト入力エリアが表示される
3. タスクのタイトルを入力する（例：「レポートを書く」）
4. 「追加」ボタンを押す

**結果**

- 入力したタイトルのカードが、該当カラムに追加される
- データが自動保存され、ブラウザを閉じても残る

**例外**

- タイトルが空のまま「追加」を押すと、警告メッセージが表示されカードは追加されない

---

### UC-02 タスクを進める

| 項目 | 内容 |
|------|------|
| **アクター** | ユーザー |
| **事前条件** | カードが1枚以上存在し、最も右の列（完了）にはいない |

**操作手順**

1. 進めたいカードの「進める →」ボタンを押す

**結果**

- カードが1つ右の列へ移動する（例：未着手 → 進行中）
- 移動後のデータが自動保存される

**例外**

- すでに「完了」列にあるカードは「進める →」ボタンが押せない状態（無効化）

---

### UC-03 タスクを編集する

| 項目 | 内容 |
|------|------|
| **アクター** | ユーザー |
| **事前条件** | 編集したいカードが存在する |

**操作手順**

1. 編集したいカードのタイトル部分をクリックする
2. タイトルがテキスト入力欄に変わる
3. 内容を書き換える
4. `Enter` キーを押すか、入力欄の外をクリックして確定する

**結果**

- カードのタイトルが新しい内容に更新される
- データが自動保存される

**例外**

- `Esc` キーを押すと変更がキャンセルされ、元のタイトルに戻る
- タイトルを空にして確定しようとすると、変更されずに元に戻る

---

### UC-04 タスクを削除する

| 項目 | 内容 |
|------|------|
| **アクター** | ユーザー |
| **事前条件** | 削除したいカードが存在する |

**操作手順**

1. 削除したいカードの「✕」ボタンを押す
2. 「このタスクを削除しますか？」という確認ダイアログが表示される
3. 「OK」を押して削除を確定する

**結果**

- カードがボードから削除される
- データが自動保存される

**例外**

- 確認ダイアログで「キャンセル」を押すと、削除されずにそのまま残る

## 6. 非機能要件

機能そのものではなく、「どのように動くべきか」という品質・制約の条件を定義する。

| 分類 | 要件 |
|------|------|
| **環境・互換性** | 最新バージョンのChrome・Edge・Safariで正常に動作すること。インストール不要でHTMLファイルをブラウザで開くだけで使用できること。 |
| **レスポンシブ** | PC（1280px以上）とスマートフォン（400px程度）の両方で崩れずに表示されること。 |
| **データ永続性** | ブラウザのlocalStorageを使用してデータを保存する。同一ブラウザ・同一デバイスでのみ保持される。複数デバイス間の同期はスコープ外。 |
| **セキュリティ** | ユーザーが入力したテキストはHTMLエスケープ処理を行い、XSS（スクリプトインジェクション）を防止すること。 |
| **外部依存** | 外部サーバーやAPIへの通信は行わない。すべての処理はブラウザ内で完結する。 |
| **ファイル構成** | HTMLファイル1つ（`index.html`）にCSS・JavaScriptをすべて内包する。追加ファイルなし。 |

---

## 7. スコープ外（今回は作らないもの）

以下の機能は今回の開発対象に含まない。必要であれば将来のバージョンで検討する。

| 機能 | 理由 |
|------|------|
| ユーザー認証（ログイン） | 個人利用のため不要 |
| 複数デバイス間のデータ同期 | サーバー構築が必要なため対象外 |
| チームでの共同編集 | 個人利用のため不要 |
| 期限・優先度の設定 | 初版では基本機能のみに絞る |
| 通知機能 | スコープを広げすぎないため対象外 |
| ドラッグ＆ドロップ移動 | ボタン操作で代替できるため任意扱い |
